## 本次更新（9.10.1 → 9.10.2）

> **新增 MCP 删除能力 + 客户端 0.6.2**：无数据库结构变更，覆盖解压即生效。
> 服务端补齐 5 个删除端点，客户端工具数 63 → 68。

### 新增：MCP 删除工具（5 个 · 只做软删除）

此前 MCP 只能删工时明细（`delete_effort`），任务/需求/Bug/用例/文档的删除必须回界面人工操作。
本版补齐这 5 类对象的删除端点，供 agent 在清理误建数据时使用：

| 客户端工具 | 服务端端点 | 对象 |
| --- | --- | --- |
| `zentao_delete_task` | `deleteTask` | 任务（连带子任务） |
| `zentao_delete_bug` | `deleteBug` | Bug |
| `zentao_delete_story` | `deleteStory` | 需求 |
| `zentao_delete_testcase` | `deleteTestcase` | 测试用例 |
| `zentao_delete_doc` | `deleteDoc` | 文档 |

设计约束（都经过本地实测）：

- **软删除，与界面删除等价**。走各模块**模型层**的 `delete()`（框架覆写版：`UPDATE ... SET deleted=1`
  并写入一条 `deleted` 操作记录），**不做物理 `DELETE`**，行始终留在库中、管理员可恢复；
  也**不提供恢复（undelete）工具**。之所以不调控制层：控制层的 `delete()` 被 `js::confirm` 挡着，
  且以 `die(js::...)` 输出 JS，对无会话的 MCP 请求不可用。
- **必须显式传 `confirm=yes`**。服务端 `requireConfirm()` 是硬门（缺参或传其他值 → 403
  `CONFIRM_REQUIRED`），客户端另有一层同样的本地拦截，绕过客户端也拦得住。
- **幂等保护**：对已删对象再次调用 → 403 `*_ALREADY_DELETED`；ID 不存在 → `*_NOT_FOUND`。
- **依赖联动与服务端控制层一致**：删任务会连带软删其**子任务**、回写父任务聚合状态、
  清空来源 Bug 的 `toTask`、重算所属需求阶段（返回体 `data.children` 给出连带删除的子任务数）；
  删 Bug **不会**动它转出的任务，`data.linkedTask` 给出该任务 ID 供判断。
- **删后自查**：`get_task` / `get_bug` / `get_story` 返回体新增 `deleted` 字段（1 = 已删）。
  列表类工具始终过滤已删对象，因此"列表里查不到"不能作为删除成功的判据。
- 写操作照旧受 `MCP_READONLY=1` 约束（只读模式 403 `READONLY_MODE`），并记入
  `tmp/mcp/access-YYYYMMDD.log`（署名 `personal:<account>`）。

### 是否建议升级

- **建议**（尤其需要让 agent 清理误建数据的团队）。5 个删除端点均为新增能力，不影响既有工具行为；
  唯一的可见变化是 `get_task` / `get_bug` / `get_story` 多返回一个 `deleted` 字段。
- 升级方式：可直接覆盖解压（本版无数据库变更）。
- 注意：**客户端工具与服务端端点必须成对升级**。把 0.6.2 客户端连到 9.10.1 及更早的服务端时，
  5 个删除工具会因端点不存在而失败；请先升级服务端。

### 验证记录（本地 dev 站，端到端 40 项断言全过）

- 五个对象各造一条 → **缺 `confirm` / 完全不传 `confirm` 均被服务端 403 `CONFIRM_REQUIRED`**
  （用原始签名请求绕过客户端本地拦截单独验证）→ 带 `confirm=yes` 删除成功 → 重复删除被
  `*_ALREADY_DELETED` 拒绝 → 库内确认行仍在且 `deleted=1`；
- 读取端 `get_task` / `get_bug` / `get_story` 均返回 `deleted=1`；`list_tasks` 不再出现已删对象；
- 依赖联动：父任务删除报告 `children=1` 且子任务被连带软删；`fromBug` 场景实测 `zt_bug.toTask`
  由任务 ID 清为 0，且 `zt_action` 中留下 `deleted` 操作记录；
- 不存在的 ID 五个端点均返回 `*_NOT_FOUND`；审计日志逐条落 `personal:<account>`；
- 全量 lint 通过（排除两个部分类体 ext 文件）。
