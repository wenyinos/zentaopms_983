## 本次更新（9.10.0 → 9.10.1）

> **纯热修版本**：无新增功能、**无数据库结构变更**，覆盖解压即生效。
> 修掉的两类问题都是"不会白屏所以长期没人报"的既有缺陷，其中一类影响权限页的可读性、另一类让两个功能在代码层面从未生效。

### 问题修复

- **权限提示页自己会崩（PHP Fatal，且带文件路径）**。无权限访问以下页面时，看到的不是"您无权访问"
  而是 `Fatal error`：`任务报表` / `需求报表` / `测试单报表`（`task|story|testtask|bug` 的 `report`）、
  `后台 → 注册设置/绑定/安全设置`（`admin` 的 `register|bind|safe`），以及本版的
  `统计 → 年度总结`。根因：`module/user/view/deny.html.php` 取"方法的中文名"时，遇到
  **与语言组对象同名的键**（`$lang-><模块>-><方法名> = new stdclass()`，全仓共 8 处这样的撞车）
  就把它当字符串 `printf` 出去。现已加类型守卫，非字符串一律回退到原始方法名。
  实测：`task-report` / `story-report` / `admin-safe` / `report-annualData` 由 Fatal 页恢复为权限提示。

- **「保持登录」从未生效**。`za` / `zp` 两个凭据 cookie 一直被 `identifyByCookie()` 读取，
  却从未登记进 `config/filter.php`；`filterParam = 2` 会把未登记的 cookie 直接丢掉，
  于是该功能在代码层面就是死的（本部署走统一认证票据兜底，所以一直没被发现）。
  同时补上文档紧凑版面开关 `feedbackView`。实测（直接调过滤函数做 A/B）：
  修复前只保留 `lang, theme`；修复后 `lang, theme, za, zp, feedbackView` 均保留，
  而无规则的非法键依然被拒 —— 护栏没有松动。
  注意：本版**不提供共享密钥通道**，客户端仍需各自持有个人密钥（见 9.10.0 的「安全」节）。

- **需求列表页不记忆排序**。`projectModel::story()` 的签名默认值是 `order_desc`，使
  "URL 未带 orderBy 时读 cookie"那段成为死代码。默认值改为空串、兜底仍取 `order_desc`
  （不改变既有默认排序）。实测：先以 `pri_desc` 访问写入 cookie，再不带头参数访问 ——
  cookie 未被回写、表头「P」列仍带排序标记，即排序已按 cookie 生效。

### 文档更正（关于 9.10.0 的一条说明）

- 9.10.0 的更新说明里把"CSV 导入遇 UTF-8 BOM"写成"会报编码错误"，**该描述不准确**。
  实测确认真实后果是**第一列被静默丢弃**：带 BOM 时只有第一列的列名匹配不上，其余列照常命中，
  所以既不报错也不触发编码兜底；若第一列恰好是必填项，预览页会直接是空的。
  修复本身（走统一 CSV 解析层，剥 BOM）有效且已在 9.10.0 交付，此处仅更正描述。

### 是否建议升级

- **建议**。权限页变成 Fatal 页对访客与受限账号都是可见问题；「保持登录」与排序记忆则属日常体验。
- 升级方式：可直接覆盖解压（本版无数据库变更）。
