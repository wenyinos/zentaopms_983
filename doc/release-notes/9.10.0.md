## 本次更新（9.9.1 → 9.10.0）

> 本版为 **22.6 功能移植批次**的交付版本；含新增数据库表，**升级需执行升级脚本**（见下方 CLI 通道）。

### 一、新功能

- **看板升级**：泳道维度扩展为 需求 / 模块 / 指派人 / 优先级；支持**同列拖拽排序**（顺序按泳道维度分别保存在 `zt_config`，零表结构变更；跨列拖拽仍走状态流转表单，不绕过状态机）；泳道可折叠（状态只存浏览器本地）。
- **用例库导出**：用例库支持**按当前浏览条件或勾选导出 CSV**，字段与导入模板同构（`步骤`/`预期` 成对），可"导出 → 修改 → 再导入"闭环；附件列输出「标题 + 可下载地址」；列表页新增「导出用例 / 编辑库 / 删除库」入口。
- **错误日志**：新增 `errorlog` 后台页面（请求追踪 ID 串联同一请求的多条错误、按级别过滤、7 天自动清理）。框架层在 `saveError()` 里落库，`tmp/log` 之外多一个能自助看堆栈的入口；写库失败一律吞掉，绝不影响正常响应。
- **年度总结**：`report|annualData`，以年为维度给出登录/动作/待办/工时/贡献的雷达与月度趋势，依赖 eCharts。
- **需求跟踪矩阵**：项目需求页新增矩阵视图，每行一个需求，列出所属迭代与关联的任务/Bug/用例（超 3 条折叠）；需求列表同时补上批量评审（带驳回原因）、批量指派、批量改计划。
- **CSV 批量导入导出**：任务 / Bug / 需求三对象支持**下载导入模板 → 导入 → 预览（逐行标注错误原因）→ 只写合法行并汇总成功/失败**；导出对 UTF-8 补 BOM（Excel 打开不再乱码），附件列输出「标题 + 可复制地址」纯文本。需求导入的状态由评审配置决定，**CSV 不能直接写「激活」绕过评审**。
- **文档/知识库增强**：目录与文档均支持拖拽排序（分别写 `zt_module.order` 与新增的 `zt_doc.order`）；文档支持**移动 / 复制（副本）**；新增**最近浏览**（`zt_docaction` 记录 view 动作、4 秒内重复访问只记一次）；新增**文档模板**——模板分类管理、模板 CRUD、「用此模板新建文档」，模板库对普通文档列表/搜索/统计完全隔离。
- **透视表（只读版）**：新增「统计 → 各行汇总表」类入口由透视表渲染，内置 5 张（Bug指派 / Bug创建 / 项目偏差 / 产品汇总 / 员工负载），带跨行合并与两级表头；旧报表页保留不删，可一键切回。

### 二、问题修复（本版独有）

- 修复用例库删除时报 `Attempt to read property on null`（控制层未先取 `$suite` 对象）。
- 修复文档目录内的文档在文档库「全部」视图不显示、「所有文档」统计少算（`getPrivDocs` 对齐 22.6 写法）。
- 修复**用例导入 / 用例库导入在带 UTF-8 BOM 的 CSV 下静默丢失第一列**（Excel「另存为 CSV」默认带 BOM）：旧实现只做列名精确匹配，带 BOM 时仅第一列的列名匹配不上、其余列照常命中，因此既不报错也不触发编码兜底，用户只会发现第一列数据没了（第一列是必填项时预览页直接为空）。现改走统一的 CSV 解析层（剥 BOM + 编码判定 + 列名精确/宽松匹配），同时修掉「用户调换列顺序会串值」的隐患。
- 版本号规则放开为支持 `9.10.0` 形式（仍拒绝官方禅道版本）。

### 三、平台/兼容

- 新增 helper 6 个（`setcookie`/`hasFeature`/`arrayColumn`/`formatHours`/`isApiRequest`/`mbPathinfo`），供后续移植使用。
- 引入 **eCharts 5.5.1 全量构建**（Apache-2.0，1.03MB）——注意不能用 `common` 构建，其不含 radar 类型。
- 按 §1.4 的升级约定全部采用**幂等**升级方法（`information_schema` 探测 + `CREATE TABLE IF NOT EXISTS` 双保险，种子行按条件插入），跨版本跳跃升级安全、重复执行安全。
- 已包含 `main` 的 9.9.1 热修（燃尽图 500）。

### 四、安全：MCP 密钥改为单通道

- **MCP 不再提供团队共享密钥**：所有请求（读与写）都必须用**个人密钥**签名 —— 个人密钥由各账号在禅道「我的地盘 → MCP密钥」自助生成（每人一把、互不相同）。服务端同时**移除了 `MCP_STRICT` 开关**（已无共享密钥可放行，开关失去意义）。
- 行为变化：以前"未生成个人密钥的账号可用共享密钥代为署名"（过渡模式），现在**未生成密钥的账号无法使用 MCP**（读写皆 401）；已生成密钥的账号读写正常，且无法被他人冒用署名。
- 升级后请确认：服务端 `module/mcp/.env` 可删掉已失效的 `MCP_SECRET` 行（保留可选的 `MCP_READONLY` / `MCP_IPS`）；每台客户端 `.env` 的 `MCP_SECRET` 填**该机操作人自己的个人密钥**。

### 升级提示

- 本版**有数据库变更**：新增 `zt_errorlog` / `zt_errorlogreq` 两张表与errorlog 清理定时任务；新增 `zt_pivot` / `zt_pivotspec` / `zt_pivotdrill` 三张表；`zt_doc` 新增 `order` 列、`zt_doclib` 新增 `type` 列（均追加列、有默认值，不改既有列语义）、新增 `zt_docaction` 表并种入一行「文档模板」库。请按下方 CLI 通道执行升级；如站点规范要求，先备份数据库。所有升级步骤幂等，重复执行安全。
