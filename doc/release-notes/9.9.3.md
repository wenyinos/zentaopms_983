## 本次更新（9.9.2 → 9.9.3）

> **纯热修版本**：无新增功能、**无数据库结构变更**，覆盖解压即生效。
> 本版集中修掉一批"日常会碰到、但都不至于白屏所以长期没人报"的既有缺陷，其中两处涉及权限与数据完整性。

### 问题修复

- **权限提示页自己会崩（PHP Fatal，还带文件路径）**。无权限访问以下页面时，看到的不是"您无权访问"
  而是 `Fatal error` 页：`任务报表` / `需求报表` / `测试单报表`（`task|story|testtask|bug` 的 `report`）、
  `后台 → 注册设置/绑定/安全设置`（`admin` 的 `register|bind|safe`）。
  根因：`module/user/view/deny.html.php` 取"方法的中文名"时，遇到**同名的语言组对象**
  （`$lang-><模块>-><方法名> = new stdclass()`，共 8 处这样的撞车）就把它当字符串 `printf` 出去。
  现已加类型守卫，非字符串一律回退到原始方法名。

- **私有用例库的归属校验被整条跳过**（权限问题）。`module/testsuite/control.php` 的删除流程里
  `$suite` 从未取值，`$suite->type == 'private' and ...` 恒为假 —— 有删除权限的人可以删掉
  **别人的私有**用例库。现已先取出 `$suite` 再判归属。

- **文档目录内的文档在「全部」视图不显示、首页「所有文档」统计少算**。
  `docModel::getPrivDocs()` 无条件按 module 过滤，`$module = 0` 时 SQL 退化成 `module IN ('0')`，
  目录内的文档被整体过滤掉。已改为"仅在指定目录时才过滤"（与上游 22.6 一致）。

- **「保持登录」从未生效**。`za` / `zp` 两个凭据 cookie 一直被 `identifyByCookie()` 读取，
  却从未登记进 `config/filter.php`；`filterParam = 2` 会把未登记的 cookie 直接丢掉，
  于是该功能在代码层面就是死的（本部署走统一认证票据兜底，所以看不出来）。
  同时补上文档紧凑版面开关 `feedbackView`。实测（直接调过滤函数 A/B）：
  修复前只保留 `lang, theme`；修复后 `lang, theme, za, zp, feedbackView` 均保留，
  而无规则的非法键依然被拒。

- **需求列表页不记忆排序**。`projectModel::story()` 的签名默认值是 `order_desc`，使
  "URL 没带 orderBy 时读 cookie"那段成为死代码。默认值改为空串、兜底仍取 `order_desc`
  （不改变既有默认排序）。

- **CSV 导入遇 UTF-8 BOM 会静默丢掉第一列**（Excel「另存为 CSV」默认带 BOM）。
  旧实现只做列名精确匹配：带 BOM 时**仅第一列的列名**匹配不上，其余列照常匹配，
  因此既不报错、也不触发编码兜底 —— 用户只会发现"第一列的数据没了"（若第一列是必填项，
  预览页直接是空的）。现已在解析前剥离 BOM，用例与用例库导入均适用。

- **看板页「导出」链接参数不全**：用了本页不存在的 `$browseType`，导出链接的 type 为空；
  且排序按 `order_asc` 会撞上 `zt_task` 没有 `order` 列。现已固定为 `id_asc + all`。

- **仪表盘「产品统计」块缺少阶段配置**：`$config->statistic->storyStages` 在 10.1 界面移植时漏搬，
  该块一旦被加到仪表盘就会 `foreach(null)` 告警且阶段行渲染不出来。默认不种这个块，故此前未暴露。

### 是否建议升级

- **建议**。其中"私有用例库可被他人删除"与"文档目录内文档不可见"两项会影响数据与日常使用。
- 升级方式：可直接覆盖解压（本版无数据库变更）。

  带/不带 BOM 的 CSV 导入结果一致（首列不再丢失）。
